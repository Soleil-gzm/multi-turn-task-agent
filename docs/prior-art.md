# Prior-art 对照清单

> 定位：W0 只读参照交付物。三份公开工作的**方法论对照**，不接入数据、不重新分发原始数据。
> 用法：每项对照给出「参照做法 → 本项目对应 → 状态 → 行动项」；状态三档：✅ 已对齐 / ⬜ 待核对 / — 不适用。
> 清单在每个里程碑评审时更新；标 ⬜ 的项是后续阶段的具体检查点，不是装饰。

## 1. 三份参照的职责边界

| 参照 | 范式 | 承担职责 | 不承担 |
| --- | --- | --- | --- |
| RiSAWOZ（Quan et al., EMNLP 2020，中文） | 对话状态跟踪（DST）+ 槽填充 | 中文对话结构、状态标注口径、E3 状态跟踪子集的规则校准 | 动作序列正确性、政策约束、任务终态判定 |
| ABCD（Chen et al., NAACL 2021，英文） | 动作序列 + 政策约束（Action State Tracking） | 状态机与动作序列的范式参照、政策约束下的动作选择 | 中文表达 |
| τ-bench（Yao et al., ICLR 2025，英文） | 工具调用 + 政策遵循 + 模拟用户 | 评测方法论：rule-based 终态比对、pass^k、模拟用户设计 | 中文、本项目业务字段 |

一句话：RiSAWOZ 管「对话长什么样」，ABCD 管「流程怎么走」，τ-bench 管「怎么判断走对了」。

**边界声明：** RiSAWOZ 的公开指标（Joint Goal Accuracy）与本项目指标（任务完成率）任务定义不同、**不可比**，不做横向比较；只在其状态跟踪子集上做评测器校准（见 A 组）。

## 2. 对照清单

### A. RiSAWOZ —— 对话结构与状态标注

| # | 参照做法 | 本项目对应 | 状态 | 行动项 |
| --- | --- | --- | --- | --- |
| A1 | 槽位-值对表示对话状态（flat slot-value） | 三态元组 `(stage, offer, round)` + facts 字典 | ⬜ | Stretch 接入或降级时产出字段映射表：哪些槽位可映射到 facts / 哪些无对应 |
| A2 | 中文语篇现象：省略、指代（如「那笔」指代合同） | 当前 Mock 关键词路由不处理；真实模型接入后由 LLM 承担 | ⬜ | 真实模型接入后，从 RiSAWOZ 摘 5–10 条省略/指代样本做意图识别冒烟 |
| A3 | 12 领域、65% 单域 / 35% 多域（跨域切换） | 对应「跑题拉回」能力，当前由状态机护栏兜底 | — | MVP 不做跨域；列入 Stretch（对应可选数据集 CrossWOZ） |
| A4 | 评测口径：turn 级状态预测 vs 标注一致性 | E3 状态跟踪子集校准：规则评测器判定 vs 标注一致率 | ⬜ | 接入窗口执行；**不与论文 JGA 横向比较**（任务定义不同） |

### B. ABCD —— 动作序列与政策约束

| # | 参照做法 | 本项目对应 | 状态 | 行动项 |
| --- | --- | --- | --- | --- |
| B1 | 55 种意图，每种意图要求特定 action 序列 | 8 个业务模块 → 12 条状态机转移 + 6 工具 | ⬜ | W2 核对：转移表粒度是否过粗/过细（对照检查点：一个意图是否对应唯一合法的下一步动作集合） |
| B2 | 政策约束显式写在流程里（先查政策 → 验证身份 → 才能承诺） | `transitions` 的 `when` 条件 + `policy` 字段（分期≤3、延期≤30、减免≤10%） | ✅ | 已由 oracle 的 forbidden_actions + 超政策拒绝话术覆盖 |
| B3 | AST 任务：给定对话历史，预测下一个 action | 状态机转移预测（facts → 合法转移集合） | ✅ | 判定边界：required 至少一次 / order 非空才校验顺序 / 部分完成按维度给分 |
| B4 | CDS 任务：判断整条对话是否成功 | E4 任务完成率（oracle 终态比对） | ✅ | stage_match + task_completed 已入 v0 报告 |
| B5 | 客户-客服双角色多轮（平均每条多轮交互） | 模拟用户（规则化 persona 脚本） | ✅ | runner.build_user_messages；升级方向见 C3 |

### C. τ-bench —— 评测方法论与模拟用户

| # | 参照做法 | 本项目对应 | 状态 | 行动项 |
| --- | --- | --- | --- | --- |
| C1 | Rule-based reward：对比最终数据库状态与标注目标状态 | E4：oracle `expected_terminal.stage` + `outcome` 与终态及目标工具调用比对 | ✅ | 已按四项口径拆分（业务目标达成 / 处置正确 / 结案 / 标签匹配），避免单一「完成率」混淆语义 |
| C2 | **pass^k**：同一 case 连跑 k 次全通过的比例（稳定性，非 pass@k 的偶然命中） | R1 稳定性指标（定义已写入评测设计并注明出处） | ⬜ | 实现排入 Stretch：runner 支持 `--repeat k` 逐 case 聚合 |
| C3 | LLM 扮演用户：有自己目标、会改变主意 | 对抗 persona 4 类（拖延/强硬/误导/试探），当前为规则化脚本 | ⬜ | W4 对抗增强时参照其 user simulator 设计：persona 目标 + 动态改主意 |
| C4 | 领域政策以书面文档形式给 agent（条款化、可引用） | 知识库片段 `POL-{主题}-{序号}` + `query_policy` 检索 | ✅ | corpus.yaml 已按条款化组织；片段 id 可被 E2 引用比对 |
| C5 | 每任务标注「期望终态 + 相关信息」作为 oracle | C1 数据契约：oracle（工具序列/参数/终态/禁用动作）+ content_hash | ✅ | 合成即 oracle，生成路径即标签 |

## 3. 已确认的借鉴结论（不再变动）

1. **终态比对 + 禁用动作**作为规则评测主干（C1 + B2）——不依赖 LLM 即可判定，满足「能用规则就不交给 LLM」。
2. **pass^k 作为稳定性指标**（C2），报告中注明出处为 τ-bench，不自称原创。
3. **政策文档条款化**（C4）——知识库 24 条片段按此组织，检索返回片段 id 供评测比对。
4. **评测器先在公开口径上校准再用**（A4）——接入 RiSAWOZ 属 Stretch；MVP 阶段可信度由「人工抽检 20 条 + 本清单的方法论出处」承担，报告中如实声明。

## 4. 引用与许可

报告中使用如下表述（评测设计 §2 同款）：

> 评测框架采用业界已验证的 agent 评测范式：终态比对（rule-based state comparison）与 pass^k 稳定性指标参考 τ-bench（Yao et al., ICLR 2025）；动作序列与政策约束的任务定义参考 ABCD（Chen et al., NAACL 2021）；中文对话结构与状态标注口径对齐 RiSAWOZ（Quan et al., EMNLP 2020）。

**许可声明：** 本项目仅使用上述数据集做方法论对照与评测器校准，不重新分发原始数据；如需使用请前往原始发布页获取并遵守其许可条款（RiSAWOZ / ABCD 为研究用途，τ-bench 为 MIT）。
